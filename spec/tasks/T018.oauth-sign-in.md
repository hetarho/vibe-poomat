# T018 OAuth sign-in & session issue
> st:todo | ssot:AUTH-1 AUTH-2 AUTH-3 AUTH-4 AUTH-5 AUTH-6 AUTH-10 AUTH-11 ARCH-18 ARCH-38 ARCH-39 ARCH-41 | base:AUTH@2 ARCH@2 | dep:T017

## goal
GitHub and Google sign-in via Arctic that creates or links an account, issues the session cookie, and emits `AccountCreated`.

## acceptance
- [ ] `GET /api/v1/auth/:provider` (github|google) → 302 to the provider authorize URL; `state` (and PKCE verifier for Google) stored in short-lived httpOnly cookies; an optional `returnTo` path is validated as a same-site relative path and stored too
- [ ] `GET /api/v1/auth/:provider/callback` → exchanges the code, fetches the provider profile (GitHub: user + primary verified email via the emails endpoint; Google: id_token claims), then runs `SignInWithProviderUseCase`
- [ ] use case resolution order: known `(provider, provider_user_id)` → load user · else verified provider email matching an existing verified identity → attach a new identity to that user (AUTH-5) · else create user + profile + generated handle and emit `AccountCreated` (AUTH-2)
- [ ] an unverified provider email never links (creates a separate account); profile prefill = provider display name + avatar URL (AUTH-3), email stored on the identity only and never returned by a public endpoint (AUTH-4)
- [ ] session created, previous session id for that browser rotated, cookie set `httpOnly, Secure, SameSite=Lax, Path=/, Max-Age=30d`; response 302 to `returnTo` or `/`
- [ ] failure paths redirect to `/(sign-in)?error=<code>` rather than rendering JSON: state mismatch, expired/invalid code, provider error, provider account with no verified email
- [ ] whole use case runs in one transaction (ARCH-38); `AccountCreated` dispatched after commit (ARCH-39)
- [ ] auth routes throttled per IP (ARCH-41)
- [ ] test: use case unit tests with in-memory repositories for all four resolution branches (known identity / link by verified email / new account / unverified email → new account) — asserting exactly one `AccountCreated` only in the create branches
- [ ] test: state-mismatch and code-exchange-failure return the redirect with the right error code, and never create a user
- [ ] test (int): full callback with the Arctic client stubbed — user, identity and session rows written, cookie attributes exactly as specified, second sign-in with the other provider on the same verified email attaches instead of creating

## impl notes
- Arctic handles authorize URL + token exchange only; profile fetching is a small per-provider adapter behind a `ProviderProfileFetcher` port so the use case stays provider-agnostic (ARCH-11)
- GitHub's primary email requires the `user:email` scope and a second API call; treat "no verified primary email" as a hard failure with its own error code — silently creating an unlinkable account would break AUTH-5 later
- config keys: `GITHUB_CLIENT_ID/SECRET`, `GOOGLE_CLIENT_ID/SECRET`, `OAUTH_REDIRECT_BASE_URL`
- session rotation on every sign-in (delete the old row if the cookie was present) ← cheap fixation defence
- `AccountCreated { userId, handle }` — the credit context subscribes in T021; nothing here knows about credits

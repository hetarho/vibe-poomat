# T034 web: project create & edit
> st:done@260908 | ssot:PROJ-1 PROJ-2 PROJ-3 PROJ-7 PROJ-8 PROJ-12 ARCH-6 ARCH-37 | base:PROJ@2 ARCH@2 | dep:T032 T022 T014

## goal
The forms for posting a project and editing it, including the live-URL check and cover image upload.

## acceptance
- [v] `/projects/new` (signed in): title ≤60 with counter, live URL (https, required), pitch ≤200 with counter, optional markdown description with preview, 1-3 tags from the fixed list as chips, optional cover upload
- [v] submitting an unreachable URL surfaces the server's `PROJECT_URL_UNREACHABLE` inline on the URL field with the observed status, and the form keeps every other value (PROJ-2)
- [v] a slow probe shows a pending state on the submit button; the form never verifies the URL itself from the browser
- [v] on success, redirect to the project page — the project is public immediately, with no draft affordance in the UI (PROJ-12)
- [v] `/projects/$id/edit` (owner only): pitch, description, tags and cover always editable; title and live URL disabled with an explanation while a mission is active (PROJ-7)
- [v] delete action on the edit page: disabled with an explanation while a mission is active, otherwise a confirmation that states the project disappears publicly while received feedback stays visible to the owner (PROJ-8)
- [v] cover upload uses the same presigned flow and client-side policy check as the avatar (T033)
- [v] markdown preview and the rendered description both sanitize HTML
- [v] test: render tests — length counters and tag cap enforced client-side, tags outside the list unavailable, unreachable-URL error lands on the field
- [v] test: with an active mission the title/URL inputs and the delete button are disabled and explain why; without one they are enabled
- [v] test: the markdown renderer strips a `<script>` and an `onerror` attribute from a fixture description

## impl notes
- FSD: `pages/project-new` and `pages/project-edit` composing `features/create-project`, `features/edit-project`, `features/delete-project`, `features/upload-image` (shared with the avatar flow) over `entities/project`
- the tag list and every length limit come from `packages/contracts` so the client and server never drift (PROJ-3, PROJ-13)
- markdown rendering: one sanitizing renderer in `shared/ui`, used by both the preview and the detail page — two renderers is how one of them ends up unsanitized

## result
Files: `apps/web/src/shared/upload/*` (new segment: `checkImage`/`imageProblem`, `useImageUpload`, `ImagePicker`), `shared/ui/markdown.tsx`+test, `shared/api/field-errors.ts` (moved down from `features/edit-profile/lib`), `entities/project/*` (rules, `serverProblems`, `project.query`, `ProjectFields`), `features/{create,edit,delete}-project/*`, `pages/project-{new,edit}/*`, `app/routes/projects.new.tsx`, `app/routes/projects.$id.edit.tsx`, `route-tree.gen.ts`; edited `features/edit-profile/*` and `entities/user` (query root).

- `features/upload-image` in the impl notes became `shared/upload`: FSD forbids a same-layer cross-import, so a feature slice could not have been reused by `features/edit-profile`, and the note's parenthetical ("shared with the avatar flow") is the requirement that matters. The avatar now runs through the same hook, policy and picker as the cover — one presign+PUT in the codebase, and `use-avatar-upload.ts` is gone. The object URL is now revoked on the next pick or on unmount rather than immediately after the upload resolves, which is what the old avatar code did.
- The description renders through one `Markdown` in `shared/ui` (react-markdown, `skipHtml`, no `rehype-raw`). HTML is dropped from the tree rather than escaped, so a `<script>` leaves no visible text either; a `javascript:` URL is refused by the default url transform. T035 must use this component for the detail page — a second renderer is the failure mode the task warned about.
- Acceptance 8's "rendered description" is only the preview in this task's scope; the detail page that renders a stored description is T035, through the same component.
- The post-create redirect uses `navigate({ href: '/projects/<id>' })` rather than typed `to`, because `/projects/$id` is T035's route. The call needs no change once it exists.
- Diverges from PROJ-7, deliberately and as the task specifies: PROJ-7 freezes the URL and the mission text but says nothing about the title, and the api lets the title change during an open mission. The edit form freezes both. update-ssot candidate: state whether the title is frozen with the URL.
- Field refusals arrive two ways and are mapped in one place (`entities/project/lib/server-problems.ts`): `VALIDATION_FAILED` with T006's details map, or a domain code (`PROJECT_TITLE_NOT_ALLOWED`, `PROJECT_URL_UNREACHABLE` with the probed `status`, …) naming exactly one field. `mergeProblems` keeps a local `null` from erasing what the server said.

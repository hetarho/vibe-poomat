# T039 web: notification settings & unsubscribe
> st:todo | ssot:NOTI-2 NOTI-3 NOTI-4 NOTI-7 ARCH-6 | base:NOTI@2 ARCH@2 | dep:T032 T030

## goal
Per-type email toggles in settings and the no-session unsubscribe landing page reached from an email.

## acceptance
- [ ] the settings section lists every NOTI-2 event type with a plain-language label and a toggle, saved individually with optimistic update and rollback
- [ ] the auto-accept warning row renders as always-on and disabled with the reason "it moves your credits" (NOTI-3)
- [ ] `/unsubscribe` reads the token from the query, calls the endpoint without requiring a session, and confirms which single email type was turned off (NOTI-4)
- [ ] an invalid or tampered token renders a plain failure state with a link to settings, and never reveals whose account it referred to
- [ ] the page states that other email types are unaffected and links to settings to re-enable
- [ ] no in-app notification inbox or bell anywhere in the UI (NOTI-7)
- [ ] test: render tests — every event type has a toggle, the warning row is disabled, a failed save rolls the toggle back
- [ ] test: the unsubscribe page renders the success state for a valid token and the failure state for an invalid one, leaking no identity in either

## impl notes
- FSD: `features/notification-preferences` over `entities/notification-preference`, mounted inside `pages/settings` (T033) and standing alone at `pages/unsubscribe`
- the unsubscribe route must render server-side without a session, so it cannot sit behind the auth guard helper from T032
- labels are written per event in the UI rather than derived from the type key — "auto-accepted" means different things to the maker and the feedbacker

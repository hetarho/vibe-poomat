## goal
Playwright coverage of the reciprocity loop end to end, the only E2E scope in v1.

## acceptance
- [ ] a test-only sign-in path (enabled solely when `NODE_ENV=test`, guarded so it cannot exist in a production build) creates a session for a fixture user without hitting GitHub or Google
- [ ] flow 1 — signup to first mission: new account gets 2 seed credits (CRED-2), posts a project with a reachable URL, opens a 2-slot mission, balance drops to 0 with 2 escrowed
- [ ] flow 2 — give feedback: a second account finds the project in the feed, claims a slot, submits a valid report, sees it pending with the 72h deadline
- [ ] flow 3 — settle: the maker accepts, the feedbacker's balance becomes 1, the mission slot count updates, and both profiles show the new counters
- [ ] flow 4 — reject: a second report is rejected with a reason, the credit returns to the maker, the report stays publicly visible with its reason, and the maker's rejection rate updates
- [ ] flow 5 — close: the maker closes the mission and the unfilled slot is refunded
- [ ] a stubbed URL probe target is served by the test fixture so project creation does not depend on the public internet
- [ ] all five flows run in CI on PRs (ARCH-28) in under 5 minutes on chromium
- [ ] no unit-level assertions in these specs — they assert only what a user can see (ARCH-21 keeps E2E to core flows)

## impl notes
- the test-only sign-in endpoint is the single sanctioned bypass; it is compiled out unless `NODE_ENV=test` and a test asserts it returns 404 in production mode ← an always-present backdoor is worse than no E2E
- each flow seeds its own accounts through the API and cleans up by truncation between specs, reusing the T005 harness rather than inventing a second one
- deterministic time: the 48h/72h timers are exercised by unit and integration tests (T027), not by E2E — no clock manipulation in the browser suite

# T002 env config package
> st:todo | ssot:ARCH-31 ARCH-15 ARCH-2 | base:ARCH@2 | dep:T001

## goal
One zod-validated env module (`@repo/config`) that is the only place in the repo reading `process.env`.

## acceptance
- [ ] `packages/config` parses and freezes env once at module load and exports the typed `env` object plus the `envSchema`
- [ ] base keys: `NODE_ENV` (development|test|production) · `LOG_LEVEL` (default info) · `API_PORT` (number, default 3001) · `API_URL` · `WEB_URL` · `DATABASE_URL` (postgres URL) — later tasks extend the same schema, never a second one
- [ ] invalid/missing env throws once at boot with every offending key listed in the message (not one-by-one)
- [ ] `.env.example` committed with every key and a safe placeholder value; `.env` gitignored
- [ ] test: valid env parses to the typed object; missing `DATABASE_URL` throws a message naming `DATABASE_URL`; a non-numeric `API_PORT` throws; unknown extra keys are ignored
- [ ] test `no-process-env.test.ts` greps `apps/**/src` and `packages/**/src` (excluding `packages/config/src`) and fails on any `process.env` occurrence

## impl notes
- zod v4 (`import { z } from 'zod'`), version pinned through the T001 catalog so contracts/nestjs-zod/drizzle-zod all share one zod ← mixed zod majors break schema interop
- parsing at import time (module side effect) is intentional per ARCH-31: a bad env fails the process immediately instead of at first use
- for tests, expose `parseEnv(raw: Record<string,string|undefined>)` and have the module-level `env` call it with `process.env` — keeps the package unit-testable without mutating the real environment
- keep secrets out of the schema's error output (print keys, never values)

# T038 web: feedback view, settle & thread

## goal
Reading a feedback report publicly, the maker's accept/reject decision, and the two-party thread.

## acceptance
- [ ] `/feedbacks/$id` renders the full report publicly (FDBK-9) with author handle/avatar or "deleted user", submission time, state, and — when rejected — the reason and note
- [ ] the maker sees Accept and Reject on a pending report; Reject requires one of the three fixed reasons with an optional note (FDBK-6)
- [ ] accept/reject show what happens to the credit before confirming (1 credit to the feedbacker / back to you — CRED-4)
- [ ] a pending report shows the auto-accept deadline (submitted + 72h) to both parties, and the maker sees the 48h warning state (FDBK-7)
- [ ] an auto-accepted report is labelled as such, distinct from a manual accept
- [ ] the thread renders oldest-first with a reply box for the two participants only; everyone else sees it read-only (FDBK-5)
- [ ] the maker's "feedback on my projects" inbox lists pending reports first with their deadlines
- [ ] settling a report that has already been settled surfaces the `FEEDBACK_ALREADY_SETTLED` message and refreshes the view rather than retrying
- [ ] test: render tests — settle controls appear only for the maker on a pending report; rejection requires a reason; the credit consequence copy matches the chosen action
- [ ] test: deadline rendering from `submitted_at` for both the 48h and 72h markers; auto-accepted label distinct from accepted
- [ ] test: the reply box is present for both participants and absent for a third party; a posted reply appears optimistically and rolls back on failure

## impl notes
- FSD: `features/settle-feedback`, `features/reply-thread` over `entities/feedback`, composed by `pages/feedback-detail` and `pages/maker-inbox`
- accepting invalidates the feedback, mission and credit balance queries together — a stale balance after a settle is the most visible cache bug in this app
- rejection copy repeats that the report stays public with its reason (FDBK-9), so makers are not surprised by their own rejection rate (FDBK-8)

# T022 project context: create, update, delete
> st:todo | ssot:PROJ-1 PROJ-2 PROJ-3 PROJ-7 PROJ-8 PROJ-12 PROJ-15 PROJ-16 ARCH-13 ARCH-14 ARCH-40 | base:PROJ@2 ARCH@2 | dep:T019 T015

## goal
The `project` bounded context: a public project with a verified live URL, editable by its owner, deletable only when no mission is active.

## acceptance
- [ ] `apps/api/src/project/` created with schema:
      `projects(id uuid pk, owner_id uuid not null, title varchar(60) not null, live_url text not null, pitch varchar(200) not null, description text, cover_key text, tags text[] not null, upvote_count integer not null default 0, deleted_at timestamptz, created_at, updated_at, index(owner_id), index(created_at desc) where deleted_at is null)`
- [ ] `POST /api/v1/projects` creates a public project immediately (no draft state, PROJ-12): title ≤60, pitch ≤200, description optional markdown (stored raw, rendered client-side), tags 1-3 from the fixed list (PROJ-3), cover key optional from T014
- [ ] live URL required, https, verified reachable through the `HttpProbe` (T015) before the row is written; unreachable → 422 `{code:"PROJECT_URL_UNREACHABLE"}` with the observed status in `details` (PROJ-2)
- [ ] `PATCH /api/v1/projects/:id` (owner only) updates pitch, description, tags, cover; `live_url` and `title`? — live_url is immutable while a mission is active (PROJ-7) and re-verified when changed otherwise; a change attempt during an active mission → 409 `{code:"PROJECT_LOCKED_BY_MISSION"}`
- [ ] `DELETE /api/v1/projects/:id` (owner only) soft-deletes: blocked with 409 while a mission is active (PROJ-8); afterwards the project disappears from all public reads while the owner can still fetch it and its archived feedback
- [ ] `GET /api/v1/projects/:id` public read (404 for soft-deleted unless the caller is the owner) including owner handle/avatar and the active mission summary when one exists
- [ ] tag list lives in `packages/contracts` as a zod enum shared with the web filter UI (PROJ-3)
- [ ] test: unit tests — title/pitch/tag-count limits, tag values outside the enum rejected, non-owner update/delete → `FORBIDDEN`
- [ ] test: URL verification is called exactly once per create and its failure prevents any write (probe stubbed)
- [ ] test (int): soft-deleted projects vanish from public reads but remain owner-readable; delete blocked while an open mission exists; `live_url` edit blocked while a mission is active and re-verified when allowed

## impl notes
- `tags text[]` with a GIN index rather than a join table ← the list is fixed and capped at 3; filtering is `tags && array[...]`
- markdown is stored raw and rendered in the web layer with a sanitizing renderer; the api never returns HTML (XSS containment in one place)
- soft delete here is explicitly justified by PROJ-8 (archived feedback stays readable to the maker), satisfying ARCH-14's "only when SSOT requires"
- the "active mission" check reads the mission table inside this same context (missions belong to PROJ, T023), so it is a plain repository call, not a cross-context read
- `upvote_count` is denormalized on the row and maintained by T024 in the same transaction as the upvote — the feed sorts by it

# T026 feedback report submit
> st:done@260908 | ssot:FDBK-3 FDBK-4 FDBK-9 FDBK-10 FDBK-12 ARCH-35 ARCH-38 | base:FDBK@2 ARCH@2 | dep:T025

## goal
Submitting the fixed-shape report against a held slot, immutable afterwards, and starting the settle timers.

## acceptance
- [v] schema `feedbacks(id uuid pk, claim_id uuid not null unique, mission_id uuid not null, project_id uuid not null, author_id uuid, first_impression text not null, stuck_at text not null, would_pay boolean not null, would_pay_reason text not null, suggestion text not null, answers jsonb not null, state text not null, rejection_reason text, rejection_note text, submitted_at timestamptz not null, settled_at timestamptz, index(mission_id), index(author_id), index(project_id))`
- [v] `POST /api/v1/claims/:id/feedback` submits: all five fields required plus one answer per mission question (FDBK-3); each required field and each answer ≥20 characters after trimming (FDBK-10) with per-field `VALIDATION_FAILED` details
- [v] only the claim holder may submit, only while the claim is `held` and not expired; claim moves to `submitted`, the 24h release job is cancelled
- [v] the report is immutable — no update or delete endpoint exists (FDBK-4, FDBK-12)
- [v] answers are stored positionally against the mission's frozen question list; a mission with zero questions accepts an empty array
- [v] submission schedules `feedback.warn` at +48h and `feedback.auto-accept` at +72h (T027 owns the handlers) and emits `FeedbackSubmitted { feedbackId, makerId, feedbackerId }`
- [v] `GET /api/v1/feedbacks/:id` is public (FDBK-9): report, state, rejection reason when rejected, author handle or `null` for a deleted account; `GET /api/v1/missions/:id/feedbacks` lists a mission's reports
- [v] `author_id` is nullable precisely so AUTH-9 can anonymize without deleting the report
- [v] test: unit tests — a 19-character field rejected naming that field, missing answer rejected, wrong user rejected, expired hold rejected
- [v] test (int): submit flips the claim, cancels the release job, schedules both timers with the right absolute times, and writes exactly one feedback row (unique on claim_id)
- [v] test (int): the public read shows a rejected report with its reason and renders a null author as "deleted user" data (author fields null, not an error)

## impl notes
- the 20-character rule is trimmed length, and whitespace-only content therefore fails ← FDBK-10 exists to block empty submissions, not to measure effort
- answers as a positional `jsonb` array mirrors the frozen questions (PROJ-7); storing question text with each answer would duplicate immutable data
- `project_id` is denormalized onto the feedback row so the maker's "feedback on my projects" and profile stats (T029) do not need a mission join on every read
- no draft state: a report is submitted in one request, matching FDBK-4's immutability

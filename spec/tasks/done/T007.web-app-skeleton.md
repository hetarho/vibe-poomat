## goal
Runnable `apps/web` TanStack Start SSR app with the FSD layout enforced by Steiger, Tailwind v4 + shadcn/ui base, and the unit + e2e test harnesses.

## acceptance
- [v] `pnpm --filter web dev` serves SSR `/` with a base shell (header with product name + auth slot placeholder, main, footer) and a 404 route; `pnpm --filter web build` produces the production output
- [v] `src/{app,pages,widgets,features,entities,shared}` exist, each slice exposing `index.ts`; `app/routes/*` files contain routing only and import from `src/pages/*` (ARCH-5)
- [v] Steiger runs in `pnpm turbo run lint` with the FSD ruleset (public-api, layer-imports, no cross-imports)
- [v] Tailwind v4 configured CSS-first (`@import "tailwindcss"` + `@theme` tokens) — no `tailwind.config.js` unless a plugin forces it
- [v] shadcn/ui initialized with `components.json` aliasing to `src/shared/ui`; Button, Input, Textarea, Dialog, Toast generated as the seed set and committed as owned source (ARCH-8)
- [v] Vitest jsdom project + Testing Library set up for `apps/web`; Playwright config with the dev server webServer hook and `apps/web/e2e/`
- [v] test: render test of the base shell (header/main/footer present, 404 route renders its message)
- [v] test: `fsd.test.ts` running Steiger over fixture slices that import upward / bypass `index.ts` and asserting both are reported
- [ ] test: `e2e/smoke.spec.ts` loads `/` and asserts the shell renders server-side (content present with JS disabled) — written and wired, but NOT executed here: see ## result

## impl notes
- TanStack Start with React 19 (ARCH-5); routes are file-based under `app/routes/`, and every route file's body is a thin wrapper over a page component ← keeps Steiger's layer rules meaningful
- no auth-aware UI here: the header shows a placeholder slot that the AUTH tasks fill; do not invent a sign-in button target
- no data fetching in this task — QueryClient/api-client wiring is T008, so the shell renders static content only
- keep the seed shadcn set small; later feature tasks add components as they need them (they are owned source, so each addition is a normal commit)
- Playwright: chromium only in local/PR runs (ARCH-28 runs it on PRs); no visual snapshots in v1

## result
- files: `apps/web/**` — `vite.config.ts` `tsconfig.json` `vitest.config.ts` `vitest.setup.ts` `playwright.config.ts` `components.json` `steiger.config.js` · `app/routes/{__root,index,$}.tsx` + committed `app/route-tree.gen.ts` · `src/router.tsx` · `src/app/styles.css` · `src/{widgets/app-shell,pages/home,pages/not-found}/**` · `src/shared/{ui,lib}/**` · `src/fsd.test.ts` · `e2e/smoke.spec.ts` · `test-fixtures/fsd/**` · plus `biome.json` and `pnpm-workspace.yaml`
- verify: 132 tests pass (root 40 + web 9 + api 80 + api int 3) · `pnpm turbo run lint typecheck test build` 17/17 with Steiger reporting no problems · `pnpm biome format --write .` no-op · both `pnpm --filter web dev` and the built `.output/server/index.mjs` serve `/` and `/nope` with header, main, footer, the home heading and the 404 message present in the server HTML
- **the e2e suite could not be executed on this machine.** Playwright's chromium needs `libnspr4`, `libnss3` and `libasound2`, which are absent and need `sudo` to install; the user chose to proceed without them. The spec file and the `webServer` hook are in place, and everything the spec asserts (header/main/footer, the home heading, the 404 page, all with JavaScript off) was verified with `curl` against both the dev server and the built SSR output. Run it with `sudo pnpm --filter web exec playwright install-deps chromium` followed by `pnpm --filter web test:e2e`; T009 runs Playwright in CI, where those libraries are present
- **the vitest catalog pin moved from 3.2.7 to 4.1.11.** This was forced, not preferred: `apps/web` needs vite 8 (`@vitejs/plugin-react@6` peers on `^8` and `resolve.tsconfigPaths` is a vite 8 option — a vite 7 build fails outright), while vitest 3 caps at vite 7. Two vites in the tree meant the web tests would transform through a different pipeline than the production build, so the runner moved up one major instead. All 132 tests pass on vitest 4 and the tree now holds exactly one vite
- ARCH-34's split of `app/` and `src/` needed two adjustments. The Start plugin resolves `router.routesDirectory` and `router.generatedRouteTree` **relative to `srcDirectory`**, so they read `../app/routes` and `../app/route-tree.gen.ts`; with `./app/...` nothing was generated and the build failed on a missing module. And `fsd/insignificant-slice` is off, because every slice reached only from a route file looks unreferenced when Steiger scans `./src` alone — the rules the acceptance names (`fsd/public-api`, `fsd/no-public-api-sidestep`, `fsd/forbidden-imports`) are all active
- `app/route-tree.gen.ts` is **committed**: turbo's `typecheck` depends on `^build` (dependencies), not on the app's own build, so a cold clone would fail typecheck without it
- Steiger's programmatic API needs both a config directory and an **absolute** target path; given either one wrong it silently reports zero diagnostics. `fsd.test.ts` records that and proves an upward import and an index.ts sidestep are both still caught
- the shadcn CLI produced three things that had to be corrected in owned source (ARCH-8): `import { cn } from "cn"` (it failed to resolve the `@/*` alias and installed a bogus `cn` package), `next-themes` for the toaster (there is no theme switcher in v1, so it reads the CSS tokens and follows the OS), and `--popover` tokens the seed palette did not carry. `radix-ui` replaced the individual `@radix-ui/*` packages, which is what the current components import
- two biome adjustments: `**/*.css` is excluded because Tailwind v4 is CSS-first and `@custom-variant` / `@theme inline` / `@apply` are not CSS biome can parse; and `useFilenamingConvention` is off for `apps/web/app/routes/**`, where the router dictates names like `$.tsx` and `__root.tsx`
- Playwright is **not** part of `pnpm turbo run test`, matching ARCH-28, which lists it separately from the turbo run. `web`'s `test` script is vitest only and `test:e2e` is its own script for T009 to call
- no SSOT divergence

# vibe-poomat — 서로의 첫 사용자가 되는 곳

> as of ARCH@2 AUTH@2 PROJ@2 CRED@2 FDBK@2 NOTI@2 | 260907 | 독자: 미래의 나

이 글을 읽으면 이 프로젝트가 무엇을 풀려는지, 어떤 갈림길에서 무엇을 골랐는지, 지금 어디까지 왔고 무엇이 아직 비어 있는지 한 번에 떠올릴 수 있습니다. 결정의 원문은 `spec/ssot/`에 있습니다. 둘이 어긋나면 `spec/ssot/`가 맞습니다.

## 왜 만드나

혼자 만든 사람에게 첫 사용자를 만들어 줍니다.

바이브 코더는 뭔가를 계속 내놓지만 아무도 쓰지 않습니다. 첫 사용자가 없으니 솔직한 피드백도 없습니다. 그래서 해결책을 쇼케이스가 아니라 **서로가 서로의 첫 사용자가 되는 구조**로 잡았습니다. 진입점은 바이브 코더지만, 문은 인디 빌더 누구에게나 열려 있습니다. 쇼케이스는 사람을 데려오는 미끼이고, 엔진은 상호 피드백입니다.

## 무엇을 만드나

엔진은 크레딧입니다. 피드백을 하나 주면 1크레딧을 벌고, 내 프로젝트에 피드백을 하나 받으려면 1크레딧을 씁니다. 1대1 교환이라 계산할 것이 없습니다.

한 바퀴는 이렇게 돕니다.

1. **가입** — GitHub이나 Google로 로그인하면 그것이 곧 가입입니다. 계정과 공개 프로필이 생기고 시드 크레딧 2개가 들어옵니다. 프로필 주소는 `/@handle`입니다. 두 곳의 인증된 이메일이 같으면 계정을 새로 만들지 않고 기존 계정에 로그인 수단만 붙입니다.
2. **프로젝트 등록** — 브라우저에서 바로 열리는 URL이 필수입니다. 설치가 필요하거나 열리지 않으면 등록이 막힙니다. 제목 60자, 한 줄 소개 200자, 정해진 목록에서 태그 3개까지 붙입니다.
3. **미션 열기** — "이걸 해보고 알려주세요"라는 할 일(1000자까지)과 질문 3개까지(각 200자까지), 그리고 슬롯 1~10개를 겁니다. 여는 순간 N크레딧이 에스크로로 잠기고, 잔액이 모자라면 열 수 없습니다. 프로젝트당 열려 있는 미션은 하나뿐입니다. 미션이 살아 있는 동안 URL과 미션 문구는 바꿀 수 없습니다. 피드백은 피드백을 준 사람이 실제로 본 것과 맞아야 하니까요.
4. **피드백** — 피드백을 줄 사람이 Start를 누르면 슬롯이 24시간 잡힙니다. 그 안에 제출하지 않으면 슬롯이 자동으로 풀립니다. 리포트 항목은 고정입니다. 첫인상, 막힌 지점, 돈을 낼 의향(예/아니오 + 이유), 제안 하나, 그리고 미션 질문에 답한 내용. 항목마다 20자 이상 써야 하고, 제출하면 수정할 수 없습니다.
5. **정산** — 메이커가 수락하면 1크레딧이 피드백을 준 사람에게 갑니다. 거절하려면 사유 세 가지 중 하나를 골라야 하고, 크레딧은 메이커에게 돌아갑니다. 72시간 동안 아무 응답이 없으면 자동으로 수락되고, 48시간에 경고 메일이 갑니다.
6. **다시 처음으로** — 피드백을 준 사람은 이제 크레딧이 있으니 자기 미션을 엽니다.

미션은 슬롯이 다 정산되면 완료됩니다. 메이커가 언제든 닫을 수도 있고, 열고 30일이 지나면 만료됩니다. 닫히거나 만료될 때 아무도 잡지 않은 슬롯의 크레딧은 메이커에게 돌아가고, 이미 잡혀 있는 슬롯은 풀리거나 제출될 때까지 그대로 잠겨 있습니다.

알림은 이메일로만 갑니다. 받은 피드백, 스레드 답글, 수락과 거절, 자동 수락 경고와 그 결과, 미션 완료와 만료 정산 요약이 사건마다 바로 날아갑니다. 종류별로 끌 수 있지만 자동 수락 경고만은 끄지 못합니다. 크레딧이 움직이는 알림이기 때문입니다.

피드는 빈 슬롯이 있는 프로젝트를 먼저, 그중에서도 최근 미션 순으로 보여줍니다. 최근 7일 업보트로 줄 세운 인기 목록은 별도 탭에 따로 둡니다. 피드백 엔진과 자랑 공간을 섞지 않으려는 것입니다.

### 하지 않기로 한 것

범위의 경계가 이 프로젝트의 성격을 만듭니다.

- **이메일·비밀번호 로그인과 매직 링크** — 계정을 여러 개 파서 시드 크레딧만 긁어가는 것을 막습니다.
- **크레딧 구매·선물·계정 간 이체·소멸** — 1대1 교환만 남깁니다.
- **거절에 대한 이의 제기와 중재** — v1의 유일한 견제는 프로필에 공개되는 거절률입니다.
- **모바일 앱, CLI, 설치가 필요한 프로젝트, 스크린샷이나 영상만 낸 제출물** — 첫 사용자가 실제로 써봐야 하니까요.
- **초안 상태, 프로젝트당 동시 미션 여러 개, 협업자** — 모든 프로젝트는 만드는 즉시 공개고 주인은 한 명입니다.
- **앱 안 알림함, 푸시, 주간 다이제스트, 마케팅 메일** — 알림은 이메일 하나로, 사건이 생길 때마다 바로 보냅니다.
- **역할, 팀, 관리자 콘솔, 그리고 프로젝트 신고 버튼** — 모든 계정이 메이커이자 피드백을 주는 사람입니다. 운영은 손으로 합니다. 신고를 받아줄 관리 도구가 없으니 버튼도 두지 않았습니다.
- **계정 연결·병합 화면** — 이메일이 같으면 로그인할 때 알아서 붙습니다. 손으로 묶는 화면은 만들지 않습니다.
- **DM과 채팅** — 대화는 피드백에 붙은 스레드에서만 하고, 그 스레드는 메이커와 작성자만 쓸 수 있습니다. 읽는 것은 누구나 됩니다.

## 어떻게 만드나

TypeScript 하나로 위아래를 다 씁니다. pnpm 워크스페이스 모노레포에 `apps/web`, `apps/api`, `packages/*`를 두고 Turborepo로 묶습니다. 타입과 계약을 패키지 배포 없이 공유하려는 선택입니다.

**웹**은 TanStack Start(React 19, SSR)입니다. 라우팅을 타입으로 잡아주기 때문입니다. 구조는 Feature-Sliced Design이고 `app/routes/`는 얇게 유지합니다. 서버 상태는 TanStack Query, 슬라이스를 넘나드는 클라이언트 상태만 Zustand, 나머지 UI 상태는 컴포넌트 안에 둡니다. 스타일은 Tailwind v4와 shadcn/ui를 쓰되 컴포넌트 소유권은 `shared/ui`에 둡니다.

**API**는 NestJS 11에 Fastify 어댑터입니다. Nest의 DI가 Clean 아키텍처의 포트/어댑터와 그대로 맞아떨어져서 골랐습니다. 바운디드 컨텍스트마다 모듈 하나를 두고, 그 안을 `domain → application → infrastructure → presentation`으로 나눕니다. 의존은 안쪽으로만 흐릅니다. `domain`과 `application`은 프레임워크를 import하지 않습니다. Nest도, Drizzle도, HTTP도 모릅니다.

실패는 예외로 던지지 않습니다. neverthrow의 `Result<T, DomainError>`로 돌려주고, presentation의 예외 필터가 HTTP 응답으로 바꿉니다. 예상되는 실패를 타입에 드러내려는 것이고, `throw`는 프로그래머 실수에만 씁니다.

**데이터**는 PostgreSQL 16과 Drizzle입니다. 기본키는 UUIDv7, 모든 테이블에 `created_at`/`updated_at`을 둡니다. 컨텍스트를 가로지르는 외래키와 조인은 금지고, 다른 컨텍스트는 id로만 참조합니다.

**웹과 API 사이의 계약**은 손으로 맞추지 않습니다. zod 스키마를 `packages/contracts`에서 공유하고, Nest에서 OpenAPI 3.1을 생성해 `packages/api-client`의 타입으로 뽑아 씁니다. 웹은 API 타입을 절대 직접 쓰지 않고, OpenAPI가 바뀌면 다시 생성합니다.

규칙은 말이 아니라 도구가 지킵니다. FSD 경계는 Steiger, Clean 레이어 방향은 dependency-cruiser, 린트와 포맷은 Biome, 타입은 패키지별 `tsc --noEmit`이 봅니다. 검증 명령은 `pnpm turbo run test`와 `pnpm turbo run lint typecheck`입니다.

테스트는 선택이 아닙니다. 도메인과 애플리케이션은 IO 없이 단위 테스트하고 라인 커버리지 80%를 게이트로 겁니다. 인프라는 Testcontainers로 진짜 PostgreSQL을 띄워 통합 테스트하고, 엔드포인트마다 계약 테스트를 씁니다. Playwright E2E는 핵심 플로우만 덮습니다. 안쪽 루프는 빠르게, 진짜가 필요한 곳에는 진짜 DB를 쓰자는 뜻입니다.

**로그인**은 Arctic으로 GitHub과 Google의 인증 코드만 교환하고, 세션은 직접 만듭니다. 256비트 난수를 httpOnly 쿠키에 담고 세션 목록은 PostgreSQL에 둡니다. 비밀번호가 없으니 저장할 자격증명도 없습니다.

**타이머**는 pg-boss로 돌립니다. 24시간 슬롯 해제, 48시간 경고, 72시간 자동 수락, 30일 미션 만료가 전부 예약 작업입니다. 같은 PostgreSQL을 쓰기 때문에 상태를 바꾸는 트랜잭션 안에서 작업을 함께 예약할 수 있습니다. 크레딧이 움직이는 일과 그 뒤에 따라올 일이 따로 놀지 않습니다.

**여러 컨텍스트를 건드리는 흐름은 트랜잭션 하나로 묶습니다.** 피드백을 수락하면 피드백 상태, 크레딧 원장, 미션 상태가 한 번에 커밋되거나 한 번에 실패합니다. 도메인 이벤트는 커밋이 끝난 뒤에만 퍼집니다. 잔액이 잠깐이라도 어긋나 보이면 안 되기 때문입니다.

**이메일**은 Resend로 보내고 템플릿은 React Email로 씁니다. 발송은 항상 백그라운드 작업입니다. 메일이 안 나가도 크레딧 정산은 성공해야 하니까요. 개발과 테스트에서는 콘솔로 찍습니다.

**이미지**는 S3 호환 스토리지에 올립니다. 서버는 업로드 URL만 발급하고 파일은 브라우저가 직접 올립니다. 로컬은 MinIO로 같은 API를 씁니다.

**사용자가 적어낸 URL을 검사할 때**는 SSRF를 막습니다. 사설망과 루프백, 메타데이터 주소로 향하는 요청은 리다이렉트 단계마다 다시 확인해 끊습니다. 인증과 쓰기 요청에는 요청 수 제한을 겁니다. v1에는 관리자 도구가 없으니 남용은 코드로 막습니다.

배포는 VPS 한 대입니다. 앱별 Docker 이미지를 GHCR에 올리고, Caddy 뒤에서 docker compose로 굴립니다. TLS는 Caddy가 알아서 발급합니다. CI는 GitHub Actions이고, 로컬은 docker-compose로 같은 모양을 만듭니다. 캐시, 메트릭, 트레이싱은 넣지 않았습니다. 필요해질 때 넣습니다.

## 결정의 순간들

**쇼케이스를 핵심에서 뺐습니다.** Product Hunt처럼 쇼케이스를 앞에 두면 피드백이 "축하합니다"로 무너집니다. 그렇다고 혹평 중심으로 가면 아무도 올리지 않습니다. 그래서 기본 피드는 빈 슬롯을 먼저 보여주고, 업보트는 별도 탭으로 격리했습니다. 쇼케이스는 유입 통로로만 남습니다.

**크레딧은 제출이 아니라 수락에서만 줍니다.** 제출만으로 +1을 주면 성의 없는 피드백으로 크레딧을 긁는 일이 생깁니다. 자동 지급과 보너스를 섞는 절충안도 검토했지만, 양보다 질을 택했습니다. 대신 메이커가 인색해지면 피드백을 주는 쪽이 굶습니다. 그래서 안전장치를 한 묶음으로 붙였습니다. 미션을 열 때 크레딧을 미리 잠그고, 72시간 침묵은 자동 수락으로 처리하고, 거절에는 사유를 강제하고, 거절률과 사유 분포를 프로필에 공개합니다.

**로그인은 소셜만 남겼습니다.** GitHub만 두면 노코드 빌더와 디자이너가 빠지고, 이메일과 비밀번호를 열면 계정을 여러 개 파는 파밍이 들어옵니다. 그래서 GitHub과 Google 둘만 남겼습니다.

이 결정이 아키텍처에 남긴 흔적도 정리했습니다. 처음 ARCH는 비밀번호를 argon2id로 저장하는 자체 인증을 전제로 쓰여 있었습니다. 소셜 로그인만 쓰기로 한 이상 자격증명 테이블은 쓰지도 않을 공격 표면일 뿐입니다. 그래서 ARCH-18을 OAuth 전용으로 고쳤습니다. 쿠키 세션과 세션 스토어는 그대로 남겼습니다. 남의 라이브러리에 세션까지 맡기면 계정 모델을 그쪽 스키마에 맞춰야 하기 때문입니다.

**같은 이메일이면 한 계정으로 묶습니다.** GitHub과 Google에 같은 인증된 이메일이 걸려 있는데 계정을 따로 만들면, 한 사람이 시드 크레딧을 두 번 받습니다. 로그인 흐름이 한 단계 복잡해지는 대신 파밍을 막는 쪽을 택했습니다. 인증되지 않은 이메일은 절대 묶지 않습니다.

**리뷰를 N개 해야 올릴 수 있게 하자는 안을 버렸습니다.** 콜드 스타트에서 첫 사용자는 리뷰할 프로젝트가 없습니다. 대신 가입할 때 2크레딧을 주고 시작합니다. 시드만 받고 떠나는 이탈은 감수하기로 했습니다. 반대로 크레딧 게이트를 나중에 켜자는 안은 버렸습니다. 나중에 켜면 그때 사람이 빠집니다.

**가격은 1대1로 고정했습니다.** 걸린 시간에 따라 값을 다르게 매기는 안은 메이커가 시간을 축소 신고해서, 프로젝트마다 게시 수수료를 받는 안은 인기 프로젝트가 피드백 공급을 독점해서 버렸습니다.

**계정 삭제는 남이 받은 가치를 지키는 쪽으로 정했습니다.** 즉시, 되돌릴 수 없이 지웁니다. 다만 순서가 있습니다. 열려 있는 미션을 강제로 닫고, 내 미션에 들어온 대기 중 피드백을 자동 수락해서 준 사람들이 크레딧을 받게 한 다음, 내가 준 피드백은 "삭제된 사용자" 이름으로 남기고, 잔액과 에스크로를 소각합니다.

태스크 40개는 다섯 덩어리로 흐릅니다.

```
T001-T010  뼈대      모노레포·env·API·커널·DB·계약·웹·데이터레이어·CI·Docker
T011-T016  인프라    트랜잭션/이벤트 · 잡 큐 · 메일 · 스토리지 · SSRF/제한 · 배포
T017-T021  계정·크레딧 스키마·도메인 → OAuth 로그인 → 세션 가드 → 프로필 → 크레딧 원장
T022-T031  본체      프로젝트 → 미션·에스크로 → 피드 → 슬롯 → 리포트 → 정산 → 스레드 → 통계 → 알림 → 계정 삭제
T032-T040  화면      로그인 셸 → 프로필 → 프로젝트 → 피드 → 미션 → 리포트 → 정산 → 알림 설정 → E2E
```

앞의 것이 끝나야 뒤의 것을 시작할 수 있게 의존을 걸어 두었습니다. 예를 들어 크레딧 원장(T021)이 없으면 미션 에스크로(T023)를 만들 수 없고, 정산(T027)이 없으면 알림(T030)이 보낼 사건이 없습니다.

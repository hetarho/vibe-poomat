# T010 docker images & local parity
> st:todo | ssot:ARCH-29 ARCH-30 ARCH-3 ARCH-34 | base:ARCH@2 | dep:T005 T007

## goal
Multi-stage distroless Docker images for web and api plus a docker-compose stack (web, api, pg) that mirrors production locally.

## acceptance
- [ ] `apps/api/Dockerfile` and `apps/web/Dockerfile`: multi-stage — deps (pnpm fetch/install with lockfile) → build (turbo build for that app) → runtime `gcr.io/distroless/nodejs22-debian12` running the built output as a non-root user
- [ ] images build from the repo root context with a `.dockerignore` excluding `node_modules .turbo dist coverage .git`
- [ ] `docker-compose.yml` extends the T005 file with `api` (depends_on pg healthy) and `web` (depends_on api) services, env from `.env`, ports published; the `minio` service added by T014 must keep working alongside
- [ ] migrations are a distinct step, not app boot: a `migrate` one-shot compose service (or documented `pnpm db:migrate` invocation) runs before `api` accepts traffic (ARCH-13)
- [ ] `docker compose up` yields: api `/health` 200 and `/ready` 200, web `/` served with SSR content
- [ ] `scripts/docker-smoke.sh` builds both images, brings the stack up, polls `/health` `/ready` and web `/`, tears down, and exits non-zero on any failure; wired as `pnpm test:docker`
- [ ] `pnpm test:docker` is NOT part of `pnpm turbo run test` (too slow for the inner loop) and is documented as the pre-deploy check
- [ ] test: `docker-smoke.sh` is the automated verification for this task and must pass locally; its failure path is verified by pointing it at a stopped stack

## impl notes
- distroless has no shell: healthchecks cannot use `curl` inside the container — use compose-level healthchecks from the host or a tiny node one-liner as the CMD probe
- `pnpm deploy --filter=<app> --legacy` (or `--prod`) into `/app` in the build stage so the runtime image carries only that app's production deps ← keeps the monorepo out of the final layer
- web runs the TanStack Start node server output; do not serve it through a separate nginx — one process per image (ARCH-29)
- these images are built and smoke-tested locally only; pushing to GHCR and running them on the VPS behind Caddy is T016 (ARCH-30)

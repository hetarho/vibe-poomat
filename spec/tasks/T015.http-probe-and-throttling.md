# T015 outbound HTTP probe & rate limiting
> st:todo | ssot:ARCH-40 ARCH-41 ARCH-12 ARCH-17 | base:ARCH@2 | dep:T003

## goal
A SSRF-guarded outbound HTTP port for verifying user-supplied URLs, plus throttling on auth and mutating endpoints.

## acceptance
- [ ] `HttpProbe` port: `probe(url): Promise<Result<{ finalUrl, status }, DomainError>>`; adapter uses `undici` with a custom connector that re-checks the resolved IP for every connection
- [ ] rejects: non-https schemes, hosts resolving to private/loopback/link-local/CGNAT/metadata ranges (IPv4 and IPv6, including IPv4-mapped), credentials-in-URL, non-standard ports
- [ ] follows at most 3 redirects, re-validating the destination on each hop; total timeout 5s; response body read capped at 64KB and discarded
- [ ] HEAD first, falling back to a ranged GET when HEAD is not allowed (405/501); a 2xx or 3xx-terminating-in-2xx counts as reachable, everything else returns a typed `UrlUnreachableError` with the observed status
- [ ] `@nestjs/throttler` configured with PG-backed storage: strict bucket on `/auth/*` and every mutating route (keyed by session user id when present, else client IP behind the proxy via a trusted `X-Forwarded-For` hop count), loose global bucket on reads
- [ ] a throttled request returns 429 with the standard `{code:"RATE_LIMITED", message}` body from the T004 filter, not the throttler default
- [ ] test: table-driven SSRF cases (127.0.0.1, 10.x, 169.254.169.254, `[::1]`, `::ffff:127.0.0.1`, a public host that redirects to 127.0.0.1) all rejected; a public https host accepted — DNS resolution stubbed, no live network in tests
- [ ] test: timeout and 64KB cap enforced against a local test server that stalls / streams forever
- [ ] test (int): exceeding the mutating-route bucket returns 429 with the standard error shape; the counter is keyed by user when authenticated

## impl notes
- the redirect re-check is the part that matters: validating only the first hop is the classic SSRF bypass, so the connector — not a pre-flight lookup — enforces the rule at connect time
- undici over global fetch ← it exposes the connector/dispatcher hook needed for per-connection IP checks
- probe results are not cached in v1: PROJ-2 checks once at project creation, so a cache would only add staleness
- the throttler needs `trustProxy` configured on Fastify consistently with the Caddy deployment (ARCH-30): exactly one proxy hop

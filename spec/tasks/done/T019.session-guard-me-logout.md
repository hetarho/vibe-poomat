# T019 session guard, me & logout
> st:done@260908 | ssot:AUTH-7 AUTH-8 ARCH-18 ARCH-19 ARCH-35 | base:AUTH@2 ARCH@2 | dep:T018

## goal
Cookie session authentication for every route: a guard, the current-user endpoint, logout, and expired-session cleanup.

## acceptance
- [v] `SessionGuard` reads the cookie, loads the session through `SessionStore`, rejects when missing/expired with 401 `{code:"UNAUTHENTICATED"}`, and attaches `{ userId }` to the request
- [v] guard is global with an `@Public()` decorator opting routes out ← a new endpoint is protected unless it says otherwise
- [v] a valid request slides the expiry via `Session.touch` (throttled to one write per hour, T017)
- [v] `@CurrentUser()` param decorator supplies the user id; `GET /api/v1/auth/me` returns the signed-in user's profile (including private fields the public profile omits) or 401
- [v] `POST /api/v1/auth/logout` deletes the session row and clears the cookie; idempotent when already signed out
- [v] recurring `session.cleanup` job (T012, hourly) deletes rows past `expires_at`
- [v] every account has the same rights — no role checks anywhere (AUTH-7)
- [v] test: guard unit tests — no cookie / unknown id / expired row → 401; valid → request user set; `@Public()` route reachable anonymously
- [v] test: touch throttling — two requests within the hour cause one UPDATE, a request after it causes another
- [v] test (int): logout deletes the row and a subsequent request with the same cookie is 401; `me` returns the profile shape from contracts
- [v] test (int): the cleanup job removes only expired rows

## impl notes
- session lookup on every request is one indexed PG read — acceptable at v1 volume and required for instant logout; ARCH-19's `SessionStore` port is what makes a Redis swap later a one-adapter change
- the guard must run after the throttler so anonymous floods are cut before touching the DB
- `me` is the only endpoint exposing the provider email? No — AUTH-4 says the email is used for notifications only; `me` returns it because it is the owner's own data, and the contract marks it owner-only

- the guard is global and every new endpoint is protected by default, which changed `POST /api/v1/uploads` from anonymous to authenticated — exactly what T014's own note anticipated. The smoke's "an upload can be signed" check became "the guard refuses an anonymous upload"; signing is still proven, with a session, by the storage integration test
- ARCH-19 calls the port `SessionStore`; it is `SessionRepository` here, because ARCH-20 names a repository interface `<Noun>Repository` and one port cannot be both. Same role, same swap-to-Redis property
- a session past its expiry is refused but not deleted on the request path: the hourly job reclaims it, so no request ever waits on a write it did not ask for
- all four refusals (no cookie, malformed cookie, unknown id, expired row) answer with the identical body, so the endpoint tells an attacker nothing about which it was
- `POST /auth/logout` is `@Public()`: telling a browser holding a dead cookie that it is not signed in enough to sign out would be an absurd place to draw a line

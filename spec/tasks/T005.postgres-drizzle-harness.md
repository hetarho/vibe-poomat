# T005 postgres, drizzle & integration test harness
> st:todo | ssot:ARCH-13 ARCH-14 ARCH-21 ARCH-22 ARCH-29 ARCH-32 | base:ARCH@2 | dep:T003

## goal
Drizzle client + migration workflow against PostgreSQL 16, a docker-compose PG for local dev, and the Testcontainers harness every `*.int.test.ts` uses.

## acceptance
- [ ] `docker-compose.yml` with a `pg` service (`postgres:16`), named volume, healthcheck, port from `.env`; `pnpm db:up` / `pnpm db:down` scripts
- [ ] `src/shared/db`: a Nest `DbModule` providing the Drizzle node-postgres client under a `Symbol('DB')` token, pool sized from config, closed on shutdown
- [ ] `drizzle.config.ts`: schema glob `apps/api/src/*/infrastructure/persistence/schema.ts`, `out: apps/api/drizzle`, dialect postgresql
- [ ] `pnpm db:generate` writes migrations into `apps/api/drizzle/` (committed); `pnpm db:migrate` applies them — migrations are never applied on app boot (ARCH-13: applied on deploy)
- [ ] `src/shared/db/columns.ts` helpers: `entityId()` (uuid pk, app-generated UUIDv7, no DB default) and `timestamps()` (`created_at`/`updated_at` timestamptz not null default now()) — every table in every later task uses them (ARCH-14)
- [ ] `/ready` gains a `db` indicator running `select 1` with a 1s timeout → 503 when PG is down
- [ ] Testcontainers harness: vitest `int` project matching `*.int.test.ts`, `globalSetup` starting one `postgres:16` container, running `db:migrate` against it and exporting `DATABASE_URL`; per-test isolation by truncating all non-migration tables in `beforeEach`
- [ ] test: int test that connects through the DbModule, asserts `select 1`, and asserts the migration table exists
- [ ] test: unit test that the `db` readiness indicator returns false (→ `/ready` 503) when the query rejects

## impl notes
- driver `pg` (node-postgres) + `drizzle-orm` — not postgres.js, since Testcontainers/pool teardown is the well-trodden path here and NestJS shutdown hooks need an explicit `pool.end()`
- one container for the whole int run (globalSetup), truncate-between-tests rather than a container per file ← container startup dominates otherwise; if a future suite needs isolation it can opt into its own container
- no schema tables are created in this task — the first real tables arrive with the AUTH context; the harness must therefore tolerate an empty `drizzle/` directory
- soft delete is NOT a global default (ARCH-14): the column helpers deliberately omit `deleted_at`
- compose here declares only `pg`; the `web`/`api` services are added by T010

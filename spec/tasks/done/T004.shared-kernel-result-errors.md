# T004 shared kernel, Result & error mapping
> st:done@260907 | ssot:ARCH-10 ARCH-11 ARCH-12 ARCH-14 ARCH-17 ARCH-20 ARCH-23 | base:ARCH@2 | dep:T003

## goal
Domain building blocks (Entity/VO/DomainEvent/UUIDv7 id), the neverthrow `Result` convention, `DomainError` → HTTP mapping, and dependency-cruiser rules that enforce the Clean layering.

## acceptance
- [v] `src/shared/kernel`: `ValueObject<T>` (structural equality via `equals`), `Entity<TProps>` (identity equality on `id`), `AggregateRoot` (`pullEvents()` draining a buffer), `DomainEvent` (`name`, `occurredAt`, `aggregateId`), `EntityId` (UUIDv7 generate/parse/validate)
- [v] `src/shared/result`: `Result<T, E extends DomainError>` alias over neverthrow, `ok`/`err` re-exports, `DomainError` abstract base with readonly `code: string` + `message` + optional `details`, and `NotFoundError` `ConflictError` `ValidationError` `ForbiddenError` `UnauthorizedError` subclasses
- [v] `src/shared/presentation`: `unwrap(result)` helper that returns the value or throws `DomainHttpException(code,status,message,details)`, plus one `DomainExceptionFilter` rendering `{ code, message, details? }` (ARCH-17) for every error
- [v] status map is a single explicit table (NotFound→404, Conflict→409, Validation→422, Forbidden→403, Unauthorized→401, default→400); an unmapped/unknown throwable → 500 with code `INTERNAL`, full error logged, message not leaked to the client
- [v] `.dependency-cruiser.cjs` forbids: `domain` → `application|infrastructure|presentation`, `application` → `infrastructure|presentation`, `domain|application` → `@nestjs/*|drizzle-orm|fastify|pino`, and cross-context deep imports (`src/<a>/**` → `src/<b>/**` other than a context's public module file); runs inside `pnpm turbo run lint`
- [v] test: kernel unit tests — VO equality by value, Entity equality by id, `pullEvents` empties the buffer, EntityId rejects a non-v7 uuid
- [v] test: unit tests for every row of the status map + the unknown-error fallback; a contract test asserting the wire shape `{code,message}` for a route that returns `err(new NotFoundError(...))`
- [v] test: `layering.test.ts` runs dependency-cruiser programmatically over fixture files that violate each rule and asserts each is reported

## impl notes
- neverthrow for `Result` (ARCH-12); `throw` stays for programmer errors only — the filter turning unknown throwables into 500 is the safety net, not a supported path
- `code` values are stable public API (ARCH-17): SCREAMING_SNAKE, prefixed by context once contexts exist (`AUTH_SESSION_EXPIRED`); the base classes carry a generic default code that subclasses in each context override
- UUIDv7: use `uuid` v10+ `v7()` (or `crypto.randomUUID` only where v4 is acceptable — it is not, ARCH-14 says v7) ← time-ordered ids keep PG index locality
- kernel and result live under `src/shared` and import nothing from Nest, so `domain/` may use them freely (ARCH-11)
- validation errors from zod (T006) map onto `ValidationError` with `details` = flattened issues, so web gets field-level messages

## result
- files: `apps/api/src/shared/kernel/{value-object,entity,entity-id,domain-event,aggregate-root,index}.ts` + `kernel.test.ts` · `apps/api/src/shared/result/{domain-error,index}.ts` · `apps/api/src/shared/presentation/{http-status,domain-http-exception,unwrap,domain-exception.filter,presentation.module,index}.ts` + 3 tests · `apps/api/src/layering.test.ts` · `apps/api/{dependency-cruiser.json,.dependency-cruiser.cjs}` · `apps/api/test-fixtures/layering/**` · `apps/api/src/app.module.ts`
- verify: 85 tests pass (root 23 + api 62) · `pnpm turbo run lint typecheck test build` 9/9 with `depcruise src` reporting no violations · `pnpm biome format --write .` no-op · spec lint clean · the running app renders an unknown route as `{"code":"NOT_FOUND","message":"Cannot GET /api/v1/nope"}` at 404
- the filter distinguishes three cases rather than the two the acceptance names: a `DomainHttpException` renders its mapped status, **any other framework `HttpException` keeps its own status** with a code derived from it, and only a non-HTTP throwable becomes an opaque 500 `INTERNAL`. Without the middle case a global `@Catch()` would turn every routing 404 into a 500 — the pre-existing `/api/v1/health` 404 assertion from T003 proves it matters
- the layering rules live in `dependency-cruiser.json`, with `.dependency-cruiser.cjs` a one-line `require` of it, so the CLI used by `pnpm turbo run lint` and `layering.test.ts` read the very same rule set instead of two copies that can drift
- rule patterns are anchored as `(?:^|/)src/...` rather than `^src/...` so the identical rules apply to the real tree and to `test-fixtures/layering/src`; `$1` back-references carry the context name from `from` into `to`, which is what makes `no-cross-context-deep-import` express "any context but my own"
- `cruise()` reports nothing unless `validate: true` is passed — the CLI sets it, the programmatic API does not. The fixture tree proves all four rules still fire, and asserting the exact set also proves the legal fixtures stay legal
- dependency-cruiser 18 is ESM-only and apps/api is CommonJS, so it is loaded with a dynamic `import()`. A static `import type` is impossible here: tsc demands a `resolution-mode` attribute and Biome rejects attributes on type-only imports (`syntax/correctness/noTypeOnlyImportAttributes`). Inference through `Parameters<typeof cruise>[1]` keeps it fully typed anyway
- `EntityId.parse` returns `Result<EntityId, ValidationError>` rather than throwing, since an id arriving from outside the process is an expected failure (ARCH-12); `EntityId.generate` is the internal path. A test asserts generated ids sort in creation order, which is the whole point of v7 (ARCH-14)
- `DomainError.code` is a `readonly` field with a generic default per family, so a context overrides it (`class SessionExpiredError extends UnauthorizedError { override readonly code = 'AUTH_SESSION_EXPIRED' }`) and inherits the status — asserted in `http-status.test.ts`
- `ValueObject` compares with `node:util`'s `isDeepStrictEqual`: correct structural equality with no dependency, and `node:` builtins are not what ARCH-11 calls a framework
- `pure-layers-are-framework-free` also covers `src/shared/{kernel,result}`, not just `src/<context>/{domain,application}` — the kernel is imported by domain code, so it has to obey the same rule
- no SSOT divergence

# T009 CI pipeline
> st:done@260907 | ssot:ARCH-22 ARCH-27 ARCH-28 | base:ARCH@2 | dep:T005 T007

## goal
GitHub Actions PR pipeline running affected lint/typecheck/test/build plus Playwright, with the 80% coverage gate on domain+application.

## acceptance
- [v] `.github/workflows/ci.yml` on pull_request: checkout with `fetch-depth: 0`, pnpm + Node 22 with store cache, `pnpm turbo run lint typecheck test build --filter=...[origin/main]`
- [v] a Playwright job (browser binaries cached) running `apps/web` e2e against a built app; report uploaded as an artifact on failure
- [v] integration tests run in CI: Docker is available on the runner so the Testcontainers harness from T005 works unchanged — no separate PG service definition
- [v] vitest coverage thresholds: 80% lines enforced on `apps/api/src/*/domain/**` and `apps/api/src/*/application/**` only (ARCH-22); the run fails below threshold
- [v] PR title validated against Conventional Commits (ARCH-27)
- [v] `actionlint` runs over `.github/workflows/` as part of `pnpm turbo run lint`
- [v] this workflow covers PR verification only; the main-branch build/deploy workflow is T016 (ARCH-30 now decided) and must not be duplicated here
- [v] test: a local `pnpm turbo run test -- --coverage` run fails when a domain file's coverage drops below 80% (verified with a temporary uncovered fixture, reverted after)
- [v] test: actionlint reports an error on a deliberately broken workflow fixture

## impl notes
- concurrency group per PR with `cancel-in-progress: true` ← superseded pushes should not burn runner minutes
- turbo remote cache is not configured in v1 (no account decision); local cache only
- coverage is measured only where ARCH-22 requires it: adding web/infrastructure to the gate would make the number meaningless and block honest refactors
- the pipeline must stay green with zero bounded contexts present, so the coverage gate skips gracefully when no matching files exist

## result
- files: `.github/workflows/ci.yml` · `scripts/lint-workflows.mjs` + `scripts/lint-workflows.d.mts` · `workflows.test.ts` · `test-fixtures/workflows/broken.yml` · `apps/web/playwright.config.ts` · `apps/api/vitest.config.ts` (coverage) · root and api `package.json` scripts
- verify: 157 tests pass (root 44 + web 30 + api 80 + api int 3) · `pnpm turbo run lint typecheck test build` 17/17, now including actionlint · the same command with `--filter='...[origin/main]'` also passes · `pnpm biome format --write .` no-op
- **the coverage gate was verified in all three directions.** With no bounded contexts present it reports `Unknown% (0/0)` and exits 0, which is the graceful skip the impl notes ask for. A temporary uncovered `src/probe/domain/uncovered.ts` made it exit 1 with `Coverage for lines (0%) does not meet global threshold (80%)`; adding a test that covered every branch took it to `100% (7/7)` and exit 0. The probe files were then removed and the run confirmed clean again
- the gate measures `src/*/domain/**` and `src/*/application/**` only, as ARCH-22 requires — `src/shared/**` and infrastructure are deliberately outside it
- **actionlint on npm is a wasm library with no CLI**, so `scripts/lint-workflows.mjs` is the wrapper that `pnpm turbo run lint` calls, and `workflows.test.ts` imports the same function. A `.d.mts` sidecar types it rather than turning on `allowJs` across the root
- the broken-workflow fixture needed real actionlint checks to be meaningful: a first attempt using an unknown payload field and a non-numeric action input was reported clean. It now trips `job-needs` (a `needs` naming a job that does not exist) and two `expression` errors (an unknown context and a step output from an undeclared id), which the test asserts by kind
- `ci.yml` triggers on `pull_request` only, so nothing here overlaps the deploy workflow T016 owns. Three jobs: PR title (Conventional Commits per ARCH-27), verify (affected lint/typecheck/test/build, then the coverage gate, then `api:contract:check` that T006 left for CI), and Playwright
- the Playwright job builds the app and points the `webServer` at `node .output/server/index.mjs`, so CI exercises the artifact it would deploy; locally the same config still uses the dev server. Browser binaries are cached on the lockfile hash and the HTML report uploads only on failure
- no PG service is declared: the runner has Docker, so T005's Testcontainers harness runs unchanged inside `turbo run test`
- concurrency is grouped per PR with `cancel-in-progress`, and turbo's remote cache is deliberately unconfigured in v1
- no SSOT divergence

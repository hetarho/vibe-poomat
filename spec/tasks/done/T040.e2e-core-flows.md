## goal
Playwright coverage of the reciprocity loop end to end, the only E2E scope in v1.

## acceptance
- [v] a test-only sign-in path (enabled solely when `NODE_ENV=test`, guarded so it cannot exist in a production build) creates a session for a fixture user without hitting GitHub or Google
- [v] flow 1 — signup to first mission: new account gets 2 seed credits (CRED-2), posts a project with a reachable URL, opens a 2-slot mission, balance drops to 0 with 2 escrowed
- [v] flow 2 — give feedback: a second account finds the project in the feed, claims a slot, submits a valid report, sees it pending with the 72h deadline
- [v] flow 3 — settle: the maker accepts, the feedbacker's balance becomes 1, the mission slot count updates, and both profiles show the new counters
- [v] flow 4 — reject: a second report is rejected with a reason, the credit returns to the maker, the report stays publicly visible with its reason, and the maker's rejection rate updates
- [v] flow 5 — close: the maker closes the mission and the unfilled slot is refunded
- [v] a stubbed URL probe target is served by the test fixture so project creation does not depend on the public internet
- [v] all five flows run in CI on PRs (ARCH-28) in under 5 minutes on chromium
- [v] no unit-level assertions in these specs — they assert only what a user can see (ARCH-21 keeps E2E to core flows)

## impl notes
- the test-only sign-in endpoint is the single sanctioned bypass; it is compiled out unless `NODE_ENV=test` and a test asserts it returns 404 in production mode ← an always-present backdoor is worse than no E2E
- each flow seeds its own accounts through the API and cleans up by truncation between specs, reusing the T005 harness rather than inventing a second one
- deterministic time: the 48h/72h timers are exercised by unit and integration tests (T027), not by E2E — no clock manipulation in the browser suite

## result
Files (api): `auth/presentation/test-session.controller.ts` + `auth/test-session.module.ts` (+ int test), `shared/infrastructure/http/loopback-http-probe.ts` with `http.module.ts` choosing by env. Files (web): `e2e/flow-{1..5}-*.spec.ts`, `e2e/support/fixtures.ts`, `e2e/global-setup.ts`, `playwright.config.ts`, a nitro `/api` proxy rule in `vite.config.ts`, two test ids on T033's counters. Files (root): `scripts/e2e-db.mjs` (+ `.d.mts`), `turbo.json` globalEnv, the CI e2e job. The suite runs in about 7 seconds, well inside the five-minute budget.

- The bypass lives in the `auth` context, not a sibling `test-support/` directory: a context is entered through its module file only, and dependency-cruiser refused the sibling outright. `TestSessionModule.forEnv()` answers with an empty list unless the validated env says `test`, so the routes are absent from a production graph rather than present and guarded — the int test proves both halves in one file.
- ARCH-40's SSRF guard refuses loopback by design, so a fixture URL server on localhost could never satisfy PROJ-2. Instead `NODE_ENV=test` binds `LoopbackHttpProbe`, chosen by env in the module the way the mailer is (ARCH-36): it answers for `.test` hosts, which RFC 6761 reserves and which can never resolve, and refuses everything else so the unreachable branch stays testable. That is a deviation from the acceptance's "stubbed URL probe target is served by the test fixture" — a served target cannot work behind the guard.
- FOUND A REAL BUG, and it is why this task exists: **the dev server does not hydrate**. Its client graph pulls in `react-dom/server.browser.js` and the import throws, so React never attaches and no click does anything under `pnpm dev`. The built output hydrates correctly, which is why nothing until now caught it — the smoke spec only asserted server-rendered markup, and the unit tests run in jsdom. The suite therefore runs the built artifact, which is also what CI wanted in the first place. Needs its own task.
- Second real gap: the browser reaches the api same-origin (ARCH-30), and nothing in the repo played that role outside the deploy stack — `docker-compose.yml` has no Caddy, so the local-parity stack could not serve a browser either. The suite gets one origin from a nitro `routeRules` proxy, baked in only when `WEB_API_PROXY=1`, so production images carry no rule and Caddy stays the only proxy there. Adding Caddy to the local-parity compose is a follow-up.
- Playwright's request client will not send a `Secure` cookie over http even to loopback, though the browser will (ARCH-18 makes `Secure` unconditional). Every fixture api call therefore runs inside the browser via `page.evaluate(fetch)`; a seeded actor driven through `context.request` looks signed out.
- Truncation happens once in `global-setup`, not between specs: each flow makes its own accounts and project, which is what lets the five run in parallel. CRED-3's escrow is asserted as the two claimable slots it bought, because escrow itself is nowhere in the UI — CRED-7 keeps it owner-only and no page renders it, and these specs assert only what a user can see.

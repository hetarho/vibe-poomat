# T003 api app skeleton
> st:todo | ssot:ARCH-9 ARCH-17 ARCH-31 ARCH-32 ARCH-34 ARCH-3 | base:ARCH@2 | dep:T002

## goal
Runnable `apps/api` NestJS 11 + Fastify app with pino request-scoped logging, `/health` `/ready`, and config wired through `@repo/config`.

## acceptance
- [ ] `pnpm --filter api dev` boots on `API_PORT` with the Fastify adapter; `pnpm --filter api build` emits a runnable `dist/main.js`
- [ ] global prefix `/api/v1` (ARCH-17); `/health` and `/ready` are excluded from the prefix and live at the root
- [ ] `/health` → 200 `{"status":"ok"}` unconditionally (liveness)
- [ ] `/ready` → 200 `{"status":"ready","checks":{...}}` when every registered readiness indicator passes, 503 `{"status":"not-ready","checks":{...}}` otherwise; the indicator registry is empty here and T005 registers the DB check
- [ ] pino JSON logs via nestjs-pino: every log line carries `reqId` taken from the `x-request-id` header when present, otherwise a generated UUIDv7; `LOG_LEVEL` from config; `authorization`/`cookie` headers redacted
- [ ] `app.enableShutdownHooks()` with graceful Fastify close
- [ ] structure follows ARCH-34: `src/main.ts`, `src/app.module.ts`, `src/shared/` — no bounded context yet
- [ ] test: contract tests (Nest testing module + `app.inject`) for `/health` 200 and `/ready` 200-with-no-indicators and 503-with-a-failing-fake-indicator
- [ ] test: unit test asserting an inbound `x-request-id` appears as `reqId` in the emitted log record (pino destination stubbed)

## impl notes
- `@nestjs/platform-fastify` (ARCH-9); do not add `@nestjs/platform-express` — two adapters in the tree invite the wrong import
- config: a thin `ConfigModule` provider that re-exports `@repo/config`'s `env` under a `Symbol('ENV')` token, so application code injects it instead of importing a module singleton (ARCH-11 keeps framework-free layers testable)
- readiness registry: `ReadinessRegistry` service in `src/shared/health` holding `{ name, check(): Promise<boolean> }` entries; modules register their own indicator in `onModuleInit` ← lets T005 add PG without editing the health controller
- CORS: allow `WEB_URL` only, `credentials: true` — needed for the cookie session in the AUTH tasks
- no global validation pipe here; it arrives with nestjs-zod in T006

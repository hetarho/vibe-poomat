# T013 mailer port, Resend adapter & email templates
> st:todo | ssot:ARCH-36 ARCH-35 ARCH-31 ARCH-34 | base:ARCH@2 | dep:T012

## goal
A `Mailer` port whose Resend adapter sends React Email templates from a background job, with a console adapter for development and test.

## acceptance
- [ ] `Mailer` port in `src/shared/application`: `send({ to, template, props })` — the port takes a template name + typed props, never raw HTML
- [ ] `packages/email`: React Email components + a `render(template, props)` returning `{ subject, html, text }`; templates typed by a discriminated union so an unknown name fails typecheck
- [ ] Resend adapter in production; console adapter (logs subject + recipient + a rendered text preview) in development/test — selected by `NODE_ENV`/`MAIL_DRIVER` in `@repo/config`, never by a branch inside a use case
- [ ] sending always goes through the `email.send` job (T012): callers enqueue, the handler renders and calls the port
- [ ] from address and display name come from config (`MAIL_FROM`, `MAIL_FROM_NAME`); every template renders the "replies are not accepted" line and a footer slot for the unsubscribe link that T030 fills
- [ ] a Resend API failure throws so pg-boss retries; a 4xx from Resend (bad address) is treated as permanent and dead-letters immediately without retry
- [ ] one placeholder template (`account-welcome`) proves the pipeline end to end; the real templates arrive with T030
- [ ] test: `render` snapshot for the placeholder template (subject, text fallback present, HTML contains the CTA URL)
- [ ] test: the console adapter records the send in dev; the Resend adapter is called with the rendered payload (HTTP stubbed)
- [ ] test (int): enqueueing `email.send` runs the handler once and calls the mailer once; a retriable failure is retried, a 4xx is not

## impl notes
- templates live in `packages/email` rather than the api so that copy changes never rebuild api domain code, and so the web app could preview them later ← the api adapter only imports `render`
- text fallback is mandatory (deliverability): React Email's plain-text renderer, not a hand-written duplicate
- config keys added here: `MAIL_DRIVER` (resend|console), `RESEND_API_KEY` (required only when driver=resend, conditional zod refinement), `MAIL_FROM`, `MAIL_FROM_NAME`
- no queue-level dedupe of identical emails: NOTI-1 is one email per event, and job idempotence already prevents double sends of the same job

# T034 web: project create & edit

## goal
The forms for posting a project and editing it, including the live-URL check and cover image upload.

## acceptance
- [ ] `/projects/new` (signed in): title ≤60 with counter, live URL (https, required), pitch ≤200 with counter, optional markdown description with preview, 1-3 tags from the fixed list as chips, optional cover upload
- [ ] submitting an unreachable URL surfaces the server's `PROJECT_URL_UNREACHABLE` inline on the URL field with the observed status, and the form keeps every other value (PROJ-2)
- [ ] a slow probe shows a pending state on the submit button; the form never verifies the URL itself from the browser
- [ ] on success, redirect to the project page — the project is public immediately, with no draft affordance in the UI (PROJ-12)
- [ ] `/projects/$id/edit` (owner only): pitch, description, tags and cover always editable; title and live URL disabled with an explanation while a mission is active (PROJ-7)
- [ ] delete action on the edit page: disabled with an explanation while a mission is active, otherwise a confirmation that states the project disappears publicly while received feedback stays visible to the owner (PROJ-8)
- [ ] cover upload uses the same presigned flow and client-side policy check as the avatar (T033)
- [ ] markdown preview and the rendered description both sanitize HTML
- [ ] test: render tests — length counters and tag cap enforced client-side, tags outside the list unavailable, unreachable-URL error lands on the field
- [ ] test: with an active mission the title/URL inputs and the delete button are disabled and explain why; without one they are enabled
- [ ] test: the markdown renderer strips a `<script>` and an `onerror` attribute from a fixture description

## impl notes
- FSD: `pages/project-new` and `pages/project-edit` composing `features/create-project`, `features/edit-project`, `features/delete-project`, `features/upload-image` (shared with the avatar flow) over `entities/project`
- the tag list and every length limit come from `packages/contracts` so the client and server never drift (PROJ-3, PROJ-13)
- markdown rendering: one sanitizing renderer in `shared/ui`, used by both the preview and the detail page — two renderers is how one of them ends up unsanitized

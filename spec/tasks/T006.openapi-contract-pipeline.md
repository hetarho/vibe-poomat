# T006 openapi contract pipeline
> st:todo | ssot:ARCH-15 ARCH-16 ARCH-17 ARCH-4 | base:ARCH@2 | dep:T004

## goal
Shared zod contracts, an OpenAPI 3.1 document generated from Nest, and the typed `@repo/api-client` the web app consumes.

## acceptance
- [ ] `packages/contracts`: zod schemas + inferred types exported per domain namespace; ships the cross-cutting ones now — `errorSchema` `{code, message, details?}`, `cursorPageSchema(item)` `{items, nextCursor}` (ARCH-17), and the primitives (`entityId`, `isoDate`)
- [ ] api DTOs are built from contracts schemas via `nestjs-zod` `createZodDto`; a global `ZodValidationPipe` rejects bad input as 422 through T004's `ValidationError` shape (not nestjs-zod's default body)
- [ ] `pnpm openapi:generate` builds the OpenAPI 3.1 JSON from a standalone Nest app (no listening server) into `packages/api-client/openapi.json`
- [ ] `pnpm client:generate` runs `openapi-typescript` over that file into `packages/api-client/src/schema.d.ts`; both scripts chained as `pnpm api:contract`
- [ ] `@repo/api-client` exports a configured `openapi-fetch` client factory: base URL argument, `credentials: 'include'`, and a response middleware turning any non-2xx `{code,message,details?}` body into a thrown typed `ApiError` (with `status`, `code`)
- [ ] lint-stage check `pnpm api:contract && git diff --exit-code` fails when the committed openapi.json/schema.d.ts are stale
- [ ] test: contract test that a DTO built from a contracts schema rejects a bad payload with 422 and the `{code:"VALIDATION_FAILED", details:[...]}` shape
- [ ] test: unit tests for the api-client middleware — 404 body becomes `ApiError` with `code`, a 2xx body passes through typed, a non-JSON 500 becomes `ApiError{code:"INTERNAL"}`

## impl notes
- nestjs-zod version must be the zod-v4-compatible line (matches the T002 catalog pin); if it is not, the whole workspace stays on the zod version nestjs-zod supports — one zod in the tree is non-negotiable
- `@nestjs/swagger` + nestjs-zod's `patchNestJsSwagger()`/`zodToOpenAPI` path so schemas come from zod, never hand-written decorators (ARCH-16)
- web NEVER hand-writes API types (ARCH constraint): `@repo/api-client` is the only source; contracts is for schemas shared by both sides (form validation reuse), api-client for wire types
- error `details` for validation = zod flattened `fieldErrors`, so the web form layer can map them by field name
- generated files are committed (not gitignored) so `--filter=...[origin/main]` builds do not need a running Nest app

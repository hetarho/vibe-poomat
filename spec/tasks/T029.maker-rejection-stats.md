# T029 maker rejection stats
> st:todo | ssot:FDBK-8 FDBK-6 CRED-7 AUTH-7 | base:FDBK@2 CRED@2 AUTH@2 | dep:T027

## goal
Public rejection rate and reason distribution on a maker's profile — the only check on maker power in v1.

## acceptance
- [ ] application service `getMakerStats(userId)` → `{ settledCount, rejectedCount, rejectionRate, reasons: { task_not_done, no_substance, spam_abuse } }` computed over feedback on projects the user owns
- [ ] auto-accepted reports count as accepted (they were never rejected) and pending ones are excluded from both numerator and denominator
- [ ] the profile response (T020) carries the stats block; `rejectionRate` is null when `settledCount` is 0 so the UI can say "no history yet" instead of showing 0%
- [ ] exposed publicly (FDBK-8) with no role gating (AUTH-7)
- [ ] the query is a single grouped aggregate over `feedbacks` by owner, using the denormalized `project_id`→owner lookup, and is covered by an index that keeps it out of a sequential scan
- [ ] test: unit tests over a fixture set — mixed accepted/rejected/auto-accepted/pending produce the documented rate and per-reason counts; a maker with no settled feedback yields null
- [ ] test (int): the aggregate matches a naive recount over the same rows, and the profile endpoint returns the block

## impl notes
- computed on read rather than maintained as counters ← volumes are tiny in v1 and a stale counter on a public trust signal is worse than a slightly slower profile query
- the denominator is settled feedback, not submissions: a maker cannot lower their rate by leaving reports pending, because pending ones auto-accept at 72h anyway (FDBK-7)
- no time window: FDBK-8 does not define one, and a lifetime rate is the harsher, simpler signal
